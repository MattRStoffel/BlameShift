# BlameShift

A bad clone of git whith almost no useful features

## Why BlameShift?

- Because you like to work with tools that dont exsactly work the way you would expect

### Student Learning Outcomes

Upon successful completion of the BlameShift project, students will:

- Understand Version Control Systems (VCS):
  Gain insight into the key components and features of version control systems like Git (commits, diffs, branches, merges, etc.).
- Learn CLI Development:
  Build command-line interface (CLI) applications using the Cobra framework, including designing commands, flags, and handling user input.
- Explore Data Management Techniques:
  Investigate how data is stored and retrieved in a VCS, even if those systems don’t yet support full functionality.
- Implement Basic VCS Concepts:
  Implement core features of a VCS, such as tracking file changes, committing changes, and possibly branching or merging.
- Problem Solving and Debugging:
  Encounter and troubleshoot real-world issues that arise when building complex systems, especially when creating a minimalistic or experimental project.
- Understand the Limitations of VCS Systems:
  Discover and identify the challenges involved in building a fully functional version control system, including conflict resolution, remote repositories, and efficient data storage.
- Version Control Integration:
  Explore the role of version control in modern software development and learn about existing tools like Git to understand where and why BlameShift falls short of production-level VCS systems.

## Features (none of which have been implemented)

- ❌ **Version Control**: Track changes.
- ❌ **Branching and Merging**: Work on different features simultaneously.
- ❌ **Commit History**: View a history of commits made.
- ❌ **Diff and Patch**: Compare changes between versions and apply updates.
- ❌ **Tagging**: Mark specific points in your project’s history as important.
- ❌ **Remote Repositories**: Pushing and pulling changes to/from a shared repository.
- ❌ **Stashing**: Save your work-in-progress without committing it.
- ❌ **Rebasing**: Reapply commits on top of another base tip.
- ❌ **Conflict Resolution**: Tools to help resolve merge conflicts.
- ❌ **Hooks**: Automate tasks with pre-commit, post-commit, and other hooks.
